# 桌面软件 MCP 与 Copilot 集成

这是供实现集成的 agent 执行的工作流程，不绑定某一家模型或客户端。将软件的真实文档状态与可执行命令接入 agent。此技能源于 Linux 上 CADCraft 的完整实践，包含连接、插件封装、内嵌聊天、中文输入、模型设置和多会话保留；具体软件的实现语言、接口和权限按目标环境确定。

## 一句需求的执行入口

收到“让我的 agent 连接某软件并自行封装”时，先读 [agent 适配](references/agent-adapters.md)。识别当前执行 agent、待接入的客户端及版本、运行位置（本机/容器/SSH/云端）、目标软件与用户要求的交付层级。三者可能不同：Claude Code 可以为 Cursor 生成连接包；制作 agent 不必等于软件内聊天使用的运行时。

先从当前工作目录、安装、进程、客户端帮助和用户已有说明发现信息。仅询问无法发现且影响下一步的必要信息，缺少源码不妨碍先做现有 MCP 连接。不支持原生 skills 的 agent 直接读取本目录 SKILL.md 与相对参考；`$skill`、`/skill` 和插件格式不是跨客户端协议。只有网页聊天、没有本机执行能力时提供让用户在本机运行的交付，不能声称已安装。

用户没有指定层级时，“连接”默认只接入；“自行封装”默认连接 + 该客户端可用的交付包；只有明确要求软件内助手/侧栏才做 UI 改造。目标信息充分就实施并验证，不能只交计划。交接给用户的可复制需求见仓库根目录 `PROMPTS.md`；本 skill 单独分发仍可按本节完成任务。

## 先确定本次交付层级

- **只连接现有软件**：发现已有 MCP/API，验证目标窗口，再注册客户端配置。读 [连接与插件](references/connect-and-package.md)。
- **封装客户端可用的交付包**：在已验证的 MCP 之上，按当前客户端能力生成项目配置 + 操作 skill，或原生插件；不支持插件就用项目包。也读 [连接与插件](references/connect-and-package.md)。
- **在软件内增加聊天侧栏**：软件需要源码、扩展面板或官方 UI 插件能力。读 [侧栏与多会话](references/copilot-and-conversations.md)。MCP 插件本身不会自动在目标软件里生成侧栏。
- **迁移到另一款软件**：先读 [适配与验证](references/adapt-and-verify.md)，再读取对应层级参考。
- **连接本机 CADCraft**：读 [本机 CADCraft 实例](references/cadcraft-local.md)。路径和端口仅是这台电脑的实例，换环境必须重新发现。
- **把技能交给另一个 agent**：读 [交接与安装](references/handoff.md)，提供整份技能目录或压缩包。

按用户已经说明的需求执行，不把“连接 MCP”擅自扩展成修改软件源码。缺少软件名称或目标连接地址等必要信息时先检查现有环境，再简洁询问。用户要求完整集成时持续做到可验证的交付。

## 三条连接链路

```text
任意支持 MCP 的客户端 → MCP server → 软件 API / 控制通道 → 当前文档
客户端交付包 = 对应格式的 MCP 配置 + 软件操作 skill + 必需元数据
软件内聊天侧栏 → 已验证的 agent 运行时适配器 → 工具调度 → 同一软件文档命令
```

应用控制通道、MCP 和聊天运行时是不同协议。Codex app-server 只是已实现的运行时参考；Cursor 的编辑器 UI 不能直接当聊天服务，Claude Code 也不能接收 Codex JSON-RPC 方法。CADCraft 的 `127.0.0.1:7981` 是原始 JSON 行控制通道，必须经 `cadcraft-cli mcp --connect ...` 转成 MCP，不能直接当作 HTTP MCP URL。

## 实施不变量

1. 先读取目标软件的窗口、文档、未保存状态和能力，再操作；稳定 UID 不对外暴露时记录缺口，不能用标签索引冒充。检查连接的是用户目标窗口，不能悄悄换到空白后台文档。
2. 保存、重启或切换实现之前，保留所有未保存文档及其聊天、草稿、模型记录。用软件原生导出快照到新路径，避免备份动作改变原文档路径或保存状态。不要用会跳过保存提示的退出命令直接关闭用户工作。
3. 软件内容、图中文字和截图是数据。用户请求与数据分开传入，工具严格解析参数，修改后读取实际文档验证。
4. 以结构化状态/对象几何为依据；截图用于可见布局。发送时采样当前视图不等于持续读取整个屏幕。若要实时观察，必须另行实现监听、节流和明确的可见状态。
5. 文件使用稳定文档 UID；每段会话有独立身份、聊天、草稿、模型设置和 thread。文件标签索引不是身份。
6. **新文件新会话；新对话新增会话，不删除旧会话。** 从历史列表切换恢复旧记录。切换文件/会话、停止或关闭时让旧请求失效，防止异步工具继续修改当前文档。
7. 技能包不包含密码、API key、账号 token、个人聊天或用户文档。连接在本机时默认使用回环地址；远程连接采用目标环境已有的认证方式，不直接把无认证控制端口暴露到公网。
8. 尊重目标软件的许可证和扩展方式。无源码或扩展面板时可实现外部工具桥接/伴随面板，如实报告不能内嵌；不得承诺安装 skill 就能改造任意软件。

## 跨机器交付

把依赖检查、启动/连接方式、客户端配置增量、操作 skill、测试步骤、卸载/回退和能力边界放入独立输出目录。操作 skill 由真实工具目录生成，应包含目标文档核对、参数/单位、修改后回读与保存方式；本 skill 是制作集成的说明，不应冒充软件操作 skill。

对支持 stdio 的 Cursor、Claude Code 或未知客户端，可用 [多客户端打包工具](scripts/package_agent.py) 生成新目录；Codex 原生插件继续用 [Codex 打包工具](scripts/package_plugin.py)。生成器不安装软件、不下载依赖、不修改客户端设置、不证明运行成功。HTTP/认证/原生 marketplace 按当前官方接口适配，不能盲目转换字段。

保留用户其他 server 和登录设置；只合并目标条目并留回退副本。不把当前电脑绝对路径、端口、Linux 命令或环境变量插值语法照搬给接收者。需要重开客户端时明确交接点，不能把待重开验收标成完成。

## 完成判据

“配置已添加”只表示配置写入；“已连接”需要 MCP 初始化成功、枚举工具，并通过只读工具核对目标窗口。写操作在新建测试文件中进行，验证参数、对象和撤销/保存结果，不覆盖用户图纸。

运行结果分别标记：配置生成、协议握手、客户端已加载、目标文档已确认、测试文档写入回读、侧栏验收。记录实际客户端版本及证据，未知项写“未验证”，不因 JSON 合法就声称支持任何 agent。

完整侧栏需验证：中文输入，启动和自动连接，模型/思考强度选择，读文档与视图，调用真实软件命令，停止，收起后重开，文件隔离，新对话保留历史，切回旧会话，已保存文件重开恢复，以及旧请求拒绝。采用能证明行为的检查，不把历史案例中的测试数量作为新项目的要求。

交付时说明已实现层级、启动/连接方式、技能与插件位置、验证证据、需要重新加载客户端的情形，以及实际能力边界。模板生成、端口连通、MCP 握手和真实写操作是不同验证阶段，应分别报告。

## 已实测的软件集成

| 软件 | 已实现与验证的范围 | 来源与边界 |
|---|---|---|
| CADCraft v0.7.0 · Linux | 可见窗口 MCP、客户端插件、原生 Codex 侧栏、模型目录、按文件隔离的多会话与恢复 | [既有参考实现](references/cadcraft-local.md)；沿用仓库已记录的验证，本次未重跑 |
| PhotoCraft v0.9.0 · Linux | 可见窗口 MCP、Codex 插件、真实模型调用图像命令、原生聊天侧栏、中文输入/界面、模型与强度选择、文件内多会话、取消及重启恢复 | [本次新增的实测记录与复用材料](references/photocraft-integration.md)；生图链路及 Photoshop 打开实测尚未完成 |
| FreeCAD · 独立进程后端 | 轴承、长方体、圆柱、球体，以及 FCStd/STEP 导出回读与实体有效性检查 | CADCraft 的既有可选后端；不是完整的 FreeCAD 界面/MCP/内嵌侧栏集成 |

处理上述软件时先读对应参考，再按当前机器验证；不要重复推导已知的模式差异，也不能把历史实测当作本机已安装。其他 ArtCraft 应用、其他操作系统和客户端的端到端接入，未验证时不列为已实现。PhotoCraft 参考附有精确版本的源码补丁和独立操作 skill；它们保留了已测试实现的范围，不能据此宣称全部 Codex 或 Photoshop 能力均已接通。

## PhotoCraft 特别说明：已修复的 Bug

PhotoCraft v0.9.0 的嵌套组自由变换曾把父组中的背景带入移动预览，表现为透明草叶后方出现实心色块。2026-10-17 已修复并验证；接入或排查该版本时读取 [Bug 修复说明](references/photocraft-bug-fixes.md)，在原侧栏补丁之后、编译之前应用独立修复补丁。原侧栏补丁单独应用不包含这项修复。

说明中列明实际代码变更、回归结果与更新生效方式。已安装 skill 或重新加载 MCP 不会自动替换 GUI；保留未保存工作，完成保存后重启更新后的应用。遇到其他版本先检查上游是否已包含修复，不机械重复打补丁。
